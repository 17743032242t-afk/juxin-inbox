# 聚信 · 多账号聚合收件箱

一个软件同时登录你自己的所有 Telegram 账号，所有账号收到的消息汇总在一个界面里，每条消息都标着来自哪个账号，不用切号就能看、能回。电脑和手机通用。

> 这是独立开发的第三方客户端，使用官方公开的客户端接口直连官方服务器，与 Telegram 官方无关联。

## 能做什么

| 功能 | 说明 |
|---|---|
| 多账号同时在线 | 账号数量不设上限，全部同时收消息，不用来回切换 |
| 扫码登录 | 用手机官方客户端扫一下二维码就登录，不用输手机号和验证码；也保留手机号方式 |
| 全部消息板块 | 所有账号的会话合在一个列表，最新的排最前；每条都有账号标签和颜色 |
| 按账号筛选 | 点左侧（手机在顶部）的账号，只看这一个号；再点一下回到全部 |
| 只看未读 / 搜索 | 一键只看还没回的；按联系人名字或最后一条消息搜索 |
| 不串号回复 | 回复一定从「收到消息的那个账号」发出；输入框和标题栏始终显示当前用的是哪个号 |
| 快捷回复 | 常用的话存成按钮，点一下就发出去（也可以设成只填入输入框） |
| 批量回复未读 | 勾选多个有未读的会话，一次性各回一条；带数量上限和发送间隔，保护账号 |
| 消息操作 | 引用回复、修改、删除自己发的消息、复制；查看图片；发送图片和文件（可直接粘贴截图或把文件拖进聊天窗口）；表情面板 |
| 独立窗口 | 双击会话，或点聊天标题栏右侧的按钮，把这个会话放到单独的窗口；双击左侧账号，把这个账号放到单独的窗口。可以同时开很多个，主窗口上锁时全部一起关闭 |
| 已读状态 | 单勾 = 已送达，双勾 = 对方已读 |
| 新消息通知 | 软件不在前台时弹系统通知，默认不显示消息内容 |
| 安全锁 | 主密码、自动上锁、一键上锁 |

官方客户端有、这里还没有的功能不少（下载收到的文件、贴纸、转发、建群、通话、小程序等）。完整的逐项对照、30 个独立窗口的实测速度和建议的补齐顺序见 [`功能对照表.md`](功能对照表.md)。

## 怎么用

软件是一个「可安装的网页应用」：用浏览器打开一次，就可以安装到电脑桌面或手机主屏幕，之后像普通软件一样有自己的图标和窗口。

### 先看效果（不需要任何账号）

```bash
npm ci
```

```bash
npm run demo
```

浏览器打开 `http://localhost:4174/`，里面是虚构的演示数据，可以随便点。

### 在自己电脑上用

```bash
npm ci
```

```bash
npm start
```

浏览器（Chrome 或 Edge）打开 `http://localhost:4173/`。地址栏右侧有「安装」按钮，点了以后会出现在桌面/开始菜单。

### 手机也要用：放到一个 https 网址上

手机需要通过 https 网址访问。把 `npm run build` 生成的 `dist/` 文件夹整个放到任何支持 https 的静态网站空间即可（没有后台程序，也没有数据库）。仓库里带了一个发布到 GitHub Pages 的流程（`.github/workflows/unified-inbox-pages.yml`），需要手动触发，默认不会自动运行。

手机浏览器打开网址后，选「添加到主屏幕」。

**电脑和手机各自要登录一遍账号**（每台设备只做一次）。这是故意的：同一份登录凭据如果被复制到两台设备同时使用，官方会直接把它作废。

### 第一次使用的三步

1. **设置主密码。** 每次打开软件都要输入。忘了无法找回，只能清空后重新登录各账号。
2. **填写接口参数（api_id / api_hash）。** 这是官方要求的：在 `my.telegram.org` 用你任意一个账号登录 → API development tools → 填个应用名提交，页面上就会给出这两个值。只填一次，所有账号共用。
3. **逐个添加账号，扫码即可。** 软件显示二维码 → 用手机上已登录这个账号的官方客户端扫一下（设置 → 设备 → 关联桌面设备）→（开了两步验证的再输一次密码）→ 起个备注名、选个颜色。身边没有第二台设备可扫时，也可以改用手机号和验证码。

为什么第 2 步不能省：接口参数是官方协议强制要求的，每一次连接（包括扫码登录）都要带上它。要让你不用填，就只能在软件里内置一份别人的参数——要么是官方客户端自己的（等于冒充官方客户端，是最容易被判「环境异常」的做法），要么是某个第三方的（很多人共用，别人滥用会连累你）。用你自己申请的那一份最稳妥，而且每台设备只填一次，之后加多少个账号都只需要扫码。

网络方面：软件直接连官方服务器，所以**你的设备本身要能连上官方服务器**（和用官方网页版的条件一样）。

## 登录环境与重要账号

官方会对「登录环境异常」的账号做限制。没有任何软件能保证不被判定，但下面这些是软件已经替你做好的，以及需要你配合的。

软件做的：

| 做法 | 说明 |
|---|---|
| 如实、稳定地上报设备信息 | 报的是这台设备真实的浏览器、系统和语言，每次一致。**不冒充官方客户端**——冒充一旦被识别，正是最典型的「环境异常」 |
| 一次登录长期使用 | 凭据加密保存，之后每次打开只是恢复连接，不会反复重新登录（反复登录是常见的触发原因） |
| 登录节奏提醒 | 两个账号之间不足 10 分钟、或一天内已登录 3 个时，会拦一下并说明风险 |
| 新登录保护期 | 刚登录的账号 24 小时内不参与批量回复（逐条回复不受影响） |
| 重要账号保护 | 标为「重要」的账号永远不参与批量回复，每分钟最多发 10 条 |
| 发送限速 | 任何账号每分钟最多发 20 条，超过会被拦下并告诉你还要等几秒 |
| 遇到官方限流立即停 | 不自动重试，不换着法子绕过 |
| 同一份登录只在一处使用 | 只允许开一个窗口；每台设备各自登录，不复制凭据 |

需要你配合的：

- **用这个账号平时常用的网络登录。** 不要用和平时不同国家的线路；登录过程中、登录后的头几天不要频繁换线路。很多人共用的廉价线路本身就容易被标记。
- **重要账号保持官方客户端也登录着。** 不要因为这里登上了就把手机上的退掉。
- **隔开登录，先次要后重要。** 先用不重要的账号把流程走通，确认没问题再登重要的。
- **登录后头 24 小时像平常一样用。** 不要改资料、换头像、大量加人或群发。
- **给重要账号开两步验证。** 这样即使验证码泄露，别人也登不上。
- **接口参数用自己申请的。** 用自己常用的老账号去申请，不要用别人给的。

如果某个账号登录时被拒绝或提示异常：不要反复重试，隔一天再试；它在官方客户端上不受影响。

## 安全设计

| 做法 | 目的 |
|---|---|
| 登录凭据用主密码加密后才写入本机（PBKDF2-SHA256 60 万次迭代 + AES-256-GCM） | 别人拿到你的浏览器数据文件也用不了账号 |
| 密钥不可导出，主密码从不保存 | 即使页面被注入脚本，也读不出密钥本身 |
| 聊天内容只在内存，不写磁盘 | 上锁、关闭后不留痕迹 |
| 只连接官方服务器；页面安全策略（CSP）禁止连接其他任何地址 | 没有第三方中转，没有统计和广告，凭据和消息发不到别处 |
| 不加载任何外部脚本、字体、图片 | 杜绝供应链上被人动手脚的入口 |
| 消息一律按纯文字显示；外部链接打开前要确认 | 对方发来的恶意代码不会被执行 |
| 一段时间不操作自动上锁；上锁即断开所有账号、清空内存里的消息 | 人离开设备时别人看不了 |
| 连续输错主密码，等待时间逐次翻倍 | 增加当面猜密码的难度 |
| 同一时间只允许开一个窗口 | 避免同一份登录被重复使用而被官方作废 |
| 移除账号时会在官方服务器上退出登录 | 凭据彻底作废，不留后患 |
| 批量回复只能回给「对方先发来且未读」的会话，限量、限速、遇限流即停 | 避免账号被官方当成骚扰而限制 |
| 每次打包生成 `SHA256SUMS.txt` | 可以核对线上文件有没有被改动 |

需要你自己注意的：

- **网址要自己掌握。** 谁能改网站上的文件，谁就能改软件。请放在你自己的账号/服务器下，不要用别人给的链接。
- **主密码要够强**，并且不要和别处重复。它是凭据被偷走后的最后一道防线。
- **第三方客户端有账号风险。** 官方允许第三方客户端，但对新申请的接口参数、短时间内登录很多账号、频繁重复发送相同内容比较敏感，个别情况下会限制或封停账号。建议：账号分几天陆续登录，不要一口气全加；批量回复不要滥用。
- **设备本身要安全。** 如果电脑或手机已经中了木马，任何软件都保护不了已解锁的内容。
- 换设备、送修之前，在「设置与安全」里点「退出所有账号并清空本机数据」。
- 在官方客户端的「设置 → 设备」里可以看到本软件的登录（应用名是你申请接口参数时填的名字，设备显示为你实际用的浏览器和系统），随时可以从那边把它下线。

## 验证到什么程度

已经验证（在开发环境里自动运行，全部通过）：

- 62 项逻辑测试：加密保险库（密文、防篡改、防降级、输错限速、改密码）、多账号汇总与不串号、已读未读、扫码登录和手机号登录的各种情况、二维码能被独立的识别库正确读出、账号失效处理、登录节奏与保护期、发送限速、批量回复的各项限制、独立窗口的已读与刷新范围、发文件。
- 界面全流程自动测试（电脑 + 手机尺寸）：设主密码 → 填接口参数 → 加两个账号（含两步验证）→ 回复 / 快捷回复 / 引用 / 修改 / 删除 → 恶意内容不执行 → 批量回复 → 本机存储只有密文 → 第二个窗口打不开 → 上锁解锁 → 刷新后解锁 → 移除账号 → 改主密码 → 清空。
- 独立窗口自动测试：会话和账号在独立窗口打开、在里面回复、实时收消息、表情面板、粘贴文件、多个窗口互不干扰、主窗口上锁时全部关闭。
- 压力测试：30 个独立窗口同时开着、连续来 1000 条消息，每条平均 3.5 毫秒画到窗口上，30 个窗口内容全部正确。
- 正式版在浏览器里能加载真实连接代码和加密模块，并且只向官方服务器发起连接，无安全策略报错。

**还没有验证的**：开发环境连不上官方服务器，所以**用真实账号登录、收发消息这一段还没有实际跑过**。连接层是按接口库的类型定义逐项核对写成的，但第一次用真实账号时仍可能遇到需要调整的地方，建议先用一个不重要的账号试。

## 开发

```bash
npm run typecheck
```

```bash
npm test
```

界面测试（含独立窗口测试）需要先启动本地服务，再另开一个终端运行：

```bash
npm start
```

```bash
npm run test:e2e
```

目录结构：

```
src/core/     不依赖界面的核心逻辑
  vault.ts          加密保险库
  hub.ts            多账号汇总中心
  batch.ts          批量回复
  mtcute-backend.ts 真实连接（基于开源库 mtcute）
  mock-backend.ts   模拟连接（测试和演示用）
src/ui/       界面（Preact）
public/       页面外壳、图标、离线缓存
test/         自动化测试
```

运行时依赖只有三个库：`@mtcute/web`（MTProto 协议实现）、`preact`（界面）、`uqr`（生成二维码，零依赖）。
